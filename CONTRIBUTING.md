# Contributing to ReoVault

Thanks for considering a contribution. ReoVault is a small, focused project;
the notes below should be enough to get a change reviewed and merged
smoothly.

## Development setup

The tests run the real `restic` and `rclone` binaries (never fakes), at the
versions pinned in the Dockerfile. Put them in `.tools/` (gitignored):

```bash
mkdir -p .tools && cd .tools
curl -fsSLO https://github.com/restic/restic/releases/download/v0.19.1/restic_0.19.1_linux_amd64.bz2
curl -fsSL https://github.com/restic/restic/releases/download/v0.19.1/SHA256SUMS | grep linux_amd64.bz2 | sha256sum -c -
bunzip2 -c restic_0.19.1_linux_amd64.bz2 > restic && chmod +x restic
curl -fsSLO https://github.com/rclone/rclone/releases/download/v1.75.2/rclone-v1.75.2-linux-amd64.zip
curl -fsSL https://github.com/rclone/rclone/releases/download/v1.75.2/SHA256SUMS | grep -a linux-amd64.zip | sha256sum -c -
unzip -p rclone-v1.75.2-linux-amd64.zip rclone-v1.75.2-linux-amd64/rclone > rclone && chmod +x rclone
cd ..
```

```bash
uv sync --dev
PATH=$PWD/.tools:$PATH uv run pytest     # unit + integration, camera-free (fake and demo cameras)
uv run ruff check . && uv run ruff format --check . && uv run mypy reovault
```

Camera-touching work (`reovault run` against real hardware, capturing
fixtures) needs `reolink-cli` installed and a real camera on the LAN.

### The dashboard

The dashboard is a SvelteKit SPA in `dashboard/` (Svelte 5, Tailwind v4,
shadcn-svelte). It talks only to the `/api/v1` JSON API, never to anything
else, and is served by the same FastAPI process in production.

```bash
cd dashboard
npm ci --ignore-scripts
npm run dev        # http://127.0.0.1:5173, proxies /api to a daemon on :8080
npm run check      # svelte-check
npm test           # vitest
npm run build      # static output in dashboard/build
```

To have `reovault daemon` itself serve a local build (what the image does):
`rm -rf reovault/web/dist && cp -r dashboard/build reovault/web/dist`.

No camera at hand? A `demo = true` entry in `[[cameras]]` is a pretend camera
with a sliding week of tiny clips (see
[Configuration](https://wiebe-vandendriessche.github.io/reovault/configuration/#cameras)).

After changing an API route or model, regenerate the client types and
commit both files (CI fails if either is stale):

```bash
uv run python scripts/export_openapi.py dashboard/openapi.json
cd dashboard && npm run gen:api
```

Design rules worth knowing before touching UI code:

* Colors come from the brand tokens in `dashboard/src/routes/layout.css`;
  `tests/unit/test_design_tokens.py` checks their WCAG contrast.
* No inline `<script>` or static `style="..."` in markup: the CSP is
  `script-src 'self'` (plus a hash of the one boot script) and
  `style-src 'self'`. Dynamic values are SVG attributes or Svelte `style:`
  bindings, which the browser applies through the CSSOM.
* Only ASCII on screen: no typographic quotes, dashes, dots or arrows, and
  no drawn separators between facts (use spacing); symbols come from the
  icon pack. `tests/unit/test_dashboard_ascii.py` enforces it.
* Components under `src/lib/components/ui/` are generated by
  `npx shadcn-svelte@1.7.0 add <name>`; prefer adding over hand-writing.

### Running from source without Docker

Deployment is Docker Compose only, but for development the daemon runs fine
from a checkout, with demo cameras and a local restic repository:

```bash
cat > reovault.toml <<'TOML'
[[cameras]]
alias = "demo"
timezone = "Europe/Brussels"
demo = true

[backup]
repository = "./data/backups"
password_file = "./data/restic_password"
interval_minutes = 15

[web]
email = "dev@example.com"
cookie_secure = false

[tools]
restic = "./.tools/restic"
rclone = "./.tools/rclone"
TOML
mkdir -p data && openssl rand -base64 32 > data/restic_password && chmod 600 data/restic_password
uv run reovault web set-password
uv run reovault doctor
uv run reovault daemon                   # backups + API + dashboard on :8080
```

For a real camera, install [`reolink-cli`](https://github.com/reolink/reolink-cli),
register it (`reolink-cli device add <alias> --host <ip> --user admin`) and
add a `[[cameras]]` entry with that alias. See the
[CLI reference](docs/cli-reference.md) for every command.

## Before implementing Reolink-related behavior

Read [`CLAUDE.md`](CLAUDE.md)'s "Research before implementation" section.
Do not assume protocol behavior, command availability, recording formats, or
camera capabilities from memory; verify against the upstream `reolink-cli`
docs/changelog or against real device behavior, and say which one a claim is
based on.

## Making a change

1. Open an issue first for anything non-trivial (new feature, behavior
   change) so the approach can be discussed before code is written.
2. Keep changes focused. A bug fix doesn't need to also refactor nearby
   code. Smaller PRs review faster.
3. Add or update tests for the behavior you're changing. Non-trivial logic
   (a branch, a parser, a security-relevant path) needs a test that would
   fail if the logic broke.
4. Run the checks above before opening a PR; CI enforces the same ones.
5. Open a PR against `main`. Fill in the PR template. It's short.

All changes land via pull request; direct pushes to `main` are disabled.

## Versioning and releases

Releases are tag-triggered (`vX.Y.Z`) and built/signed/published by CI (see
[`.github/workflows/release.yml`](.github/workflows/release.yml)). Version
bumps happen in a normal PR that updates `version` in `pyproject.toml`;
maintainers tag a release from `main` once a bump is merged.
